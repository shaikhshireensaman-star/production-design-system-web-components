Get started

01 · Setup

Getting started

From the workspace root, install packages, build, and start the demo or documentation app.

pnpm install
pnpm build
pnpm typecheck
pnpm test
pnpm --filter @production-design-system/demo dev

Import the generated package entry points:

import "@production-design-system/components";
import "@production-design-system/tokens/tokens.css";

Components are authored as native custom elements. Their TypeScript source compiles to ESM JavaScript and declarations in packages/components/dist.

02 · Catalog

Components

Button · pds-button

Attributes: variant (primary, secondary, danger), type, disabled. Default slot content; native click bubbles. Parts: button.

Primary Secondary
<pds-button variant="primary" type="submit">Save</pds-button>

Text Field · pds-text-field

Attributes: label, name, type, placeholder, required, disabled, value. Form-associated; native input/change events cross the shadow boundary.

<pds-text-field label="Email" name="email" type="email" required></pds-text-field>

Select · pds-select

Attributes: label, name, placeholder, options (JSON label/value array), required, disabled, value. Emits change.

<pds-select label="Plan" name="plan" options='[{"label":"Starter","value":"starter"}]'></pds-select>

Checkbox · pds-checkbox

Attributes: label, name, value, checked, required, disabled. Form-associated; emits change.

<pds-checkbox label="Accept terms" name="terms" required></pds-checkbox>

Radio Group · pds-radio-group

Attributes: label, name, options, value, required, disabled. Arrow keys move selection; emits change.

<pds-radio-group label="Density" name="density" options='[{"label":"Comfortable","value":"comfortable"}]'></pds-radio-group>

Switch · pds-switch

Attributes: label, name, value, checked, required, disabled. Form-associated; switch semantics and change event.

<pds-switch label="Notifications" name="notifications" checked></pds-switch>

Badge · pds-badge

Attributes: variant (success, warning, danger, info, neutral), label.

<pds-badge variant="success" label="Ready"></pds-badge>

Alert · pds-alert

Attributes: variant, title, message. Message and title are rendered as text.

<pds-alert variant="info" title="Heads up" message="Details"></pds-alert>

Card · pds-card

Optional title, default body slot, and named footer slot. Parts: base, title, content, footer.

Default slot content.

Footer slot
<pds-card title="Workspace"><p>Body</p><span slot="footer">Footer</span></pds-card>

Dialog · pds-dialog

Attributes: open, title. Methods: open(), close(). Escape and close dismiss; confirmation emits composed confirm.

Open dialog

Slotted dialog content.

const dialog = document.querySelector("pds-dialog");
dialog.open();
dialog.addEventListener("confirm", onConfirm);

Rating · pds-rating

Attributes: value, max, label, readonly, disabled. Emits composed pds-change with numeric value.

<pds-rating label="Stay rating" value="4" max="5"></pds-rating>

Tabs · pds-tabs

Pair slot="tab" and slot="panel" children. selected is the zero-based active tab. Supports Arrow keys, Home, End; emits pds-tab-change.

OverviewDetails

Overview panel content.

Additional details panel.

<pds-tabs selected="0"><span slot="tab">Overview</span><p slot="panel">Summary</p></pds-tabs>

Menu · pds-menu

Provide a trigger and items with slots. Supports Arrow keys, Home, End, and Escape.

Actions ▾
<pds-menu><span slot="trigger">Actions</span><button slot="item">Edit</button></pds-menu>

Toast · pds-toast

Attributes: open, message, optional duration in milliseconds, and type="alert". Call show(); emits pds-dismiss.

Show toast
document.querySelector("pds-toast").show();

Data Table · pds-data-table

Set src to an NDJSON endpoint. It incrementally reads newline-delimited objects, skips invalid rows, and delegates filtering/sorting to a module worker. The demo dev server provides 50,000 mock rows at /mock/orders.ndjson. Load and cancel controls are provided by the component.

<pds-data-table src="/mock/orders.ndjson"></pds-data-table>

03 · Foundation

Design tokens

Import the generated CSS from @production-design-system/tokens/tokens.css. Source values live in packages/tokens/src/tokens.json. The generator provides color, spacing, typography, radius, motion, shadow, and focus variables with light, dark, and high contrast themes.

<html data-theme="dark">
var(--pds-color-brand-600)
var(--pds-typography-font-size-base)
var(--pds-spacing-4) · var(--pds-radius-md) · var(--pds-shadow-md)

Tokens are grouped into CSS @layer tokens and @layer themes.

04 · Inclusive use

Accessibility

  • Give controls descriptive labels and meaningful action text. Text fields and selects connect labels to their native controls.
  • Radio groups and tabs support keyboard navigation; menus support Arrow keys, Home, End, and Escape.
  • Form-associated controls use ElementInternals for values and required validation in supporting browsers.
  • Dialogs use a native modal dialog element and title association.
  • Respect reduced motion and check contrast when supplying custom themes.

No formal WCAG conformance audit has been completed; run your own assistive technology and target-browser evaluation before claiming conformance.

05 · Integration

Frameworks and server rendering

Elements work with plain HTML and vanilla JavaScript. The apps/react-example workspace runs a React 19 app that passes component properties and listens to the dashed custom event directly. Start it with pnpm --filter @production-design-system/react-example dev.

Button and Card reuse an existing open shadow root on upgrade, which supports Declarative Shadow DOM. Example server output:

<pds-button>
  <template shadowrootmode="open">
    <button part="button" class="primary"><slot></slot></button>
  </template>
  Continue
</pds-button>

Load the component module on the client after the browser parses the declarative shadow root.

06 · Quality and release

Testing, security, and publishing

From the workspace root run pnpm typecheck, pnpm test, pnpm build, and pnpm test:browser. Playwright runs interaction and form journeys in Chromium, Firefox, and WebKit; the axe catalog scan and component visual baselines run in Chromium with pnpm test:visual. pnpm perf:lighthouse builds the demo, records three desktop Lighthouse runs under reports/lighthouse, and checks the configured LCP, CLS, JavaScript transfer-size, and performance-score budgets. Browser availability is required for Playwright.

Production demo and docs previews send a strict Content-Security-Policy and security response headers. There are no inline application scripts or styles, so no CSP nonce is needed. Static hosts must serve the supplied public/_headers rules as response headers; a meta CSP cannot provide the same protections. The service worker caches only same-origin navigation and static assets, never authenticated, private, or no-store responses. NDJSON input and worker messages are validated and size-limited.

Form-associated fields use ElementInternals for value, validity, reset, and state restoration; test browser support in your target matrix. Keyboard behavior and accessible names are documented beside each component. The automated axe scan is a useful regression check, not a formal WCAG conformance audit.

Packages are intentionally private pending an explicit registry and publication decision. See CHANGELOG.md for the unreleased 0.1.0 baseline and .github/workflows/release-readiness.yml for the manual, non-publishing package dry run. A release requires a reviewed version, changelog entry, registry credentials, and explicit publication approval.
